# FolderWatcher

Автоматическое преобразование CSV в JSON для macOS: программа следит за
входной папкой, проверяет данные и сохраняет результаты в отдельную папку.
Исходные CSV сохраняются. Результаты и ошибки записываются в лог.

## Требования и установка

- macOS и Python 3.9 или новее.
- Дополнительные библиотеки не требуются: используется стандартная библиотека Python.
- Права чтения входных файлов и записи в рабочие папки и лог.

Скопируйте проект в `~/Developer/FolderWatcher` (или другую доступную для записи
папку), затем откройте Terminal:

```bash
cd ~/Developer/FolderWatcher
python3 --version
python3 watcher.py
```

Если Python отсутствует или версия ниже 3.9, установите подходящий Python 3
и повторите проверку версии перед запуском.

При первом запуске автоматически создаются `source`, `output` и `watcher.log`.
Сообщение «Наблюдение запущено» означает, что программа ожидает файлы.
Оставьте Terminal работающим. Остановка — **Ctrl+C**.

Из другой папки программу можно запустить полным путём:

```bash
python3 ~/Developer/FolderWatcher/watcher.py
```

## Первый файл

Пока программа работает, сохраните в `source/clients.csv`:

```csv
name,email,active
Anna,anna@example.com,yes
Ivan,ivan@example.com,no
```

При настройках по умолчанию примерно через 5–8 секунд после обнаружения
стабильного файла появится `output/clients.json`:

```json
[
  {
    "name": "Anna",
    "email": "anna@example.com",
    "active": "yes"
  },
  {
    "name": "Ivan",
    "email": "ivan@example.com",
    "active": "no"
  }
]
```

В терминале и логе появится `clients.csv → clients.json: записей 2`.

## Формат CSV

- UTF-8, в том числе UTF-8 с BOM; разделитель — запятая.
- Обязательные столбцы: `name`, `email`, `active`, с непустыми значениями.
- Названия столбцов должны быть непустыми и уникальными.
- Нужна хотя бы одна запись; число значений должно соответствовать заголовкам.
- Дополнительные столбцы сохраняются. Все значения остаются строками.
- Формат email и допустимые значения active отдельно не проверяются.

## Настройки

Редактируйте `config.json`, затем остановите и заново запустите watcher.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `source_folder` | `source` | Входные CSV |
| `output_folder` | `output` | Результаты JSON |
| `log_file` | `watcher.log` | Журнал событий |
| `poll_interval_seconds` | `2` | Интервал проверки папки в секундах |
| `settle_seconds` | `5` | Время без замеченных изменений файла перед обработкой |

Пути считаются относительно папки с конфигом, а не текущей папки терминала.
Можно указать абсолютные пути или пути с `~`. Папки source и output не должны
совпадать или быть вложенными друг в друга. Интервалы должны быть положительными
конечными числами. Конфиг всегда берётся рядом с `watcher.py`.

## Поведение и ошибки

Обрабатываются CSV непосредственно в source, включая файлы, которые были там
до запуска. Вложенные папки, скрытые файлы и символические ссылки пропускаются.
Расширение `.CSV` также поддерживается.

Программа сравнивает размер, время изменения и идентификатор файла между
проверками. Неизменившаяся версия обрабатывается один раз за запуск.
Ожидание стабильности уменьшает риск чтения незаконченной копии, но не гарантирует,
что другая программа завершила запись. Для надёжной передачи сначала полностью
запишите файл с расширением `.tmp` в source, затем переименуйте его в `.csv`.

При ошибке CSV сообщение попадает в лог, а наблюдение продолжается. Исправьте
и сохраните файл: изменившаяся версия будет проверена снова. Ошибки записи также
логируются; после устранения причины измените исходник или перезапустите watcher
для повторной попытки.

Существующий JSON никогда не перезаписывается: выводится предупреждение.
Для новой выгрузки используйте новое имя CSV. Для повторной обработки под старым
именем сначала уберите предыдущий результат из output и перезапустите watcher.
Одного удаления JSON во время работы недостаточно для повторной обработки.

Если запись прервётся, в output может остаться неполный JSON. Уберите такой
результат перед повторной попыткой. Запускайте только один экземпляр программы
для одной пары папок. CSV целиком загружается в память; большие выгрузки требуют
соответствующего объёма свободной памяти.

Ошибки настроек или подготовки рабочих папок завершают запуск с сообщением.

## Лог

Каждая запись содержит дату, время, уровень и сообщение:

- `INFO`: запуск, успешная обработка, остановка через Ctrl+C.
- `WARNING`: существующий результат пропущен.
- `ERROR`: ошибка чтения папки или обработки файла.

При достижении примерно 1 МБ лог ротируется; сохраняются до трёх архивов
`watcher.log.1`, `watcher.log.2`, `watcher.log.3`.

## Проверка обработки ошибок

Во время работы сохраните в source новый файл `broken.csv`:

```csv
name,email,active
Ivan,,yes
```

Дождитесь ошибки о пустом email. Добавьте адрес и сохраните файл снова.
Должен появиться `output/broken.json` без перезапуска программы.

## Файлы проекта

- `converter.py` — чтение, проверка CSV и сохранение JSON.
- `watcher.py` — конфиг, лог и постоянное наблюдение.
- `config.json` — настройки.
- `README.md` — установка и использование.

## Фоновый запуск через launchd (macOS)

`local.folderwatcher.plist` — настройка пользовательского LaunchAgent.
Он запускает watcher при загрузке агента и при входе пользователя в macOS.
Terminal можно закрыть. Во время сна компьютера обработка не выполняется.
Автоматический перезапуск после аварийного завершения не настроен.

### Подготовка на другом компьютере

В plist указаны абсолютные пути для исходного компьютера. Перед установкой
замените `/Users/michellemanakov/Developer/FolderWatcher` во всех путях на вашу
папку проекта. Проверьте `command -v python3` и `python3 --version`; укажите
абсолютный путь к Python 3.9+ первым элементом `ProgramArguments`.
В plist нельзя рассчитывать на раскрытие `~` или переменных shell.

### Установка и запуск

Остановите вручную запущенный watcher через Ctrl+C, чтобы избежать двух
экземпляров. Из папки проекта выполните:

```bash
plutil -lint local.folderwatcher.plist
mkdir -p ~/Library/LaunchAgents
cp local.folderwatcher.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.folderwatcher.plist
launchctl print gui/$(id -u)/local.folderwatcher
```

При успешном запуске статус содержит `state = running` и PID.
Сохраните CSV с новым именем в source и проверьте JSON в output:
это подтверждает фактическую обработку. Запуск после выхода и повторного входа
в macOS проверяется отдельно; для проверки не оставляйте несохранённую работу.

### Остановка и повторный запуск

Остановить и выгрузить агента:

```bash
launchctl bootout gui/$(id -u)/local.folderwatcher
```

Повторно запустить:

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.folderwatcher.plist
```

`bootout` не удаляет установленный plist: при следующем входе агент может снова
загрузиться. Для удаления автозапуска сначала выгрузите агента, затем удалите
только установленную копию настройки:

```bash
rm ~/Library/LaunchAgents/local.folderwatcher.plist
```

Исходный plist в проекте и файлы данных при этом сохраняются.

После изменения config.json или кода выполните остановку и повторный запуск.
После изменения plist дополнительно скопируйте его обновлённую версию в
LaunchAgents между остановкой и запуском. Перед переключением Git-веток,
меняющим файлы работающей программы, также остановите агент.

### Диагностика

События сохраняются в `watcher.log`. Потоки процесса направляются в
`launchd.stdout.log` и `launchd.stderr.log` в папке проекта; сообщения logging
дублируются в stderr. Эти два дополнительных файла автоматически не ротируются.

Если запуск не удался, проверьте абсолютные пути в plist, версию Python,
доступность папок и содержимое `launchd.stderr.log`. Повторный bootstrap уже
загруженного агента может завершиться ошибкой: сначала проверьте его через print.
